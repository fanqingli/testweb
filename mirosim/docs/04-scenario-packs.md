# 04 三个场景包：政策、营销、品牌

场景包规定四样东西：刺激物怎么写、问什么、行为怎么选、报告怎么组织。量表与行为选项的定义在 `config/measures.yaml`，配置样例在 `examples/`。

## 1. 通用的反应结构

三个包共用同一个反应结构（`schemas/response.schema.json`），只有 `answers` 与 `behavior` 的取值随包而变：

| 字段 | 含义 | 为什么要 |
|---|---|---|
| `noticed` | 会不会停下来看 | 真实的参与度 |
| `takeaway` | 用自己的话说它讲了什么 | 发现误读——往往是最有价值的产出 |
| `inner_reaction` | 心里第一下的念头 | 与公开说法的差距本身就是信息 |
| `answers` | 量表题与开放题 | 可汇总的数字与理由 |
| `behavior` | 接下来实际最可能做的一件事 | 态度与行为常常不一致，分开问 |
| `reasons` | 一到三条简短理由 | 主题编码的原料 |
| `share` | 会不会跟人提、跟谁、怎么说 | 传播模式的输入；口口相传时的说法 |
| `quote` | 当面被问时怎么答 | 报告里引用的原话 |

样例见 `examples/response.sample.json`。

## 2. 政策包

### 2.1 刺激物

| `kind` | 内容 | 版本之间通常变什么 |
|---|---|---|
| `clause` | 条款或办法的要点 | 力度、过渡期、适用范围、豁免情形、救济渠道 |
| `subsidy` | 补贴、减免、奖励 | 金额、门槛、申领方式 |
| `notice` | 同一政策的不同发布口径 | 说法、先后顺序、由谁发布 |

写法要求：

- 给人物看的是他那个渠道上看得到的样子。配送员看到的是站点通知里的几句话，不是文件全文。同一政策可以为不同分群准备不同的呈现（内容要点相同），在 `variants[].content` 之外用 `renderings` 按渠道给出；缺省时所有人看同一段。
- 一个版本只改一个要素，否则分不清差别来自哪里。要同时比较多个要素时，用多个实验或做析因设计（版本 = 要素取值的组合，在 `attributes` 里标明）。
- 必须有现状版本。

### 2.2 人群

沿用 v3.0 §4.3 的相关方四象限，并要求回答「受影响大而话语权小的人里，谁没被代表」。每个分群填写影响权重的三个因子及依据（样例 `examples/frame.delivery_policy.yaml`）。

政策包的人群框架通常要对小群体超额抽样：加盟商只占人群的千分之五，但需要 30 人才看得出内部差别。汇总时按占比加权还原（`docs/05` §1）。

### 2.3 量表与行为

| 量表项 | 测什么 |
|---|---|
| `pol_impact` | 对自己生计的影响，变好还是变差（−2 到 2） |
| `pol_fair` | 公平感（1–5） |
| `pol_stance` | 支持 / 有条件支持 / 反对 / 无所谓 |
| `pol_condition` | 最需要改哪一点（仅对有条件支持与反对者） |
| `pol_trust_exec` | 相不相信会照写的执行（1–5） |
| `pol_worry` | 最担心的一件事 |
| `pol_info_need` | 还想知道什么 |

行为选项：照办、观望、变通规避、转嫁成本、退出、投诉反映、什么都不做。

行为这一问是政策包里最要紧的。支持率高而「观望」「变通」占多数的方案，落地时的样子和纸面上不同。

### 2.4 两种权重

| 权重 | 回答的问题 | 来源 |
|---|---|---|
| 代表性权重 | 人群里有多大比例持这种态度 | 人群框架的 `share` |
| 影响权重 | 按受影响程度加权后，意见的重心在哪 | v3.0 §5.17：暴露度、依存度、不可逆度 |

两种结果并列给出，不合成一个数。v3.0 关于权重的三条纪律（§5.17.3）继续适用：权重的依据必须写明；人数结果与加权结果必须同时展示。

### 2.5 报告结构

1. 结论摘要：各版本的排序、领先是否稳定、所处效度等级
2. 各版本对比：立场分布、行为分布（按占比加权 / 不加权 / 按影响加权）
3. 分群差异：哪些分群在版本之间变化最大
4. 反对与条件：按分群列出前三位理由，每条附原话
5. 误读清单：`takeaway` 中与条文原意不符的理解及其占比
6. 落地风险：规避、转嫁、退出行为集中在哪些分群，他们说的做法是什么
7. 信息缺口：`pol_info_need` 的主题——发布时配套解释该回答的问题
8. 研讨结果（如有）：争议结构、可交换的条件、表面服从的比例
9. 稳定性、对照检验、不适用范围、模拟声明

## 3. 营销包

### 3.1 刺激物

| `kind` | 内容 | 版本之间通常变什么 |
|---|---|---|
| `copy` | 广告或上市文案 | 诉求（功能 / 情绪 / 身份）、语气、信息量 |
| `pricing` | 价格与规格 | 价位、套餐结构、锚定价 |
| `promo` | 促销机制 | 折扣形式、门槛、期限 |
| `concept` | 产品概念描述 | 核心卖点、目标场景 |

目前只支持文字刺激物。图片、视频、包装的效果不在评估范围内；若必须评估，只能把画面内容写成文字描述，并在报告中注明评估的是描述而非素材本身。

价格测试的写法：每个价位一个版本，其余内容逐字相同；人物在每个版本里只看到一个价格，不做「你愿意付多少」的直接提问。价格反应靠版本之间的行为差来读。

### 3.2 人群

按品牌的目标用户分群（样例 `examples/frame.urban_consumers.yaml`）。分群占比应来自品牌自有的用户数据或第三方调研；没有时填估计并如实写明依据。

### 3.3 量表与行为

| 量表项 | 测什么 |
|---|---|
| `mkt_appeal` | 吸引力（1–5） |
| `mkt_relevance` | 与自己有没有关系（1–5） |
| `mkt_credible` | 信不信（1–5） |
| `mkt_unique` | 与同类比有没有不一样（1–5） |
| `mkt_price_feel` | 价格感受：便宜得可疑 / 划算 / 可接受 / 偏高 / 太高（有价格时才问） |
| `mkt_objection` | 最大的犹豫原因 |
| `mkt_annoy` | 有没有让人反感的地方 |

行为选项：这几天就买、先了解、等活动、继续用现在的、划走。

### 3.4 解读规则

- **购买意愿只用来比较，不换算成转化率。** 说「会买」的比例高于真实购买率是问卷研究里的常态，模拟只会更甚。在取得真实转化数据做校准之前（`docs/05` §6），报告只给版本间的排序与分群差异。
- **自然曝光下的结果以全体为分母。** 没看到、没在意的人都算进去。这比强制曝光下的数字低得多，也更接近实际。
- **`mkt_annoy` 单独成节。** 少数人的强烈反感比多数人的温和好感更可能演变成事件。任何版本只要有分群的反感提及率明显高于其他版本，就列为风险项。

### 3.5 报告结构

1. 结论摘要：各版本排序、领先是否稳定、所处效度等级
2. 各版本对比：四项评分、行为分布、价格感受
3. 分群差异：每个版本最吃得开和最吃不开的人群
4. 误读清单：文案被理解成了什么
5. 犹豫与反感：主题、占比、原话
6. 口口相传的说法：人物会怎么向别人转述（`share.what` 的主题）
7. 价格反应：各价位下的行为分布变化，按价格敏感度分层
8. 稳定性、对照检验（含负对照）、不适用范围、模拟声明

## 4. 品牌包

### 4.1 刺激物

| `kind` | 内容 | 版本之间通常变什么 |
|---|---|---|
| `positioning` | 品牌主张、口号、自我介绍 | 定位方向、语气 |
| `naming` | 品牌或产品名称 | 候选名称 |
| `crisis_response` | 负面事件后的回应声明 | 认不认责、补救措施、语气 |
| `extension` | 品牌延伸到新品类的设想 | 延伸方向 |

品牌刺激物的背景里要交代人物对这个品牌已知多少。两种做法：

- **虚构品牌或匿名品牌**（「一个中等价位的连锁茶饮品牌」）：人物的既有印象全部来自背景描述与其档案里的态度记录。结果干净，但不含真实品牌资产的影响。
- **真实品牌**：模型对知名品牌自带印象，这些印象来自训练数据，无法控制也无法核查其时效。使用真实品牌名时，报告必须注明这一点；合规要求见 `docs/07` §6。

缺省用第一种。

### 4.2 量表与行为

| 量表项 | 测什么 |
|---|---|
| `brd_assoc` | 看完后冒出来的三个词 |
| `brd_favor_post` | 现在的好感（−2 到 2）；与既有态度配对得出变化 |
| `brd_believe` | 它这样说自己，信不信（1–5） |
| `brd_distinct` | 与同类比有没有自己的样子（1–5） |
| `brd_self_fit` | 像不像给我这样的人准备的（1–5） |
| `brd_sincere` | 危机回应：有没有诚意（1–5） |
| `brd_blame` | 危机回应：主要是谁的责任 |

行为选项：愿意试或继续买、主动推荐、再看看、换别家、跟人吐槽、没感觉。

### 4.3 好感变化怎么量

不问「你的好感变了多少」。做法是：

```text
事前：人物档案里对该品牌的既有态度（没有则由一次不含刺激物的基线调用取得，记为版本 BASE）
事后：本次回答的 brd_favor_post
变化 = 事后 − 事前，逐人计算
```

基线调用只做一次，各版本共用。这样每个人物的变化量都是相对同一个起点。

### 4.4 危机回应的时间线

危机回应通常用群体反应接传播（样例 `examples/experiment.brand.yaml`，4 步）：

| 步 | 发生什么 | 看什么 |
|---|---|---|
| 0 | 人物看到事件本身（背景），再看到声明 | 当下的诚意评价、责任归属、好感变化 |
| 1–2 | 转述在人群中传开 | 声明被转述成什么；哪种说法传得最广 |
| 3 | 末步再问一次好感与行为 | 两周后还剩下什么 |

三版声明的差别往往不在第 0 步，而在转述：一份声明被概括成「他们说是加盟店的事」还是「他们认了、在查」，决定了没看原文的多数人的印象。

### 4.5 报告结构

1. 结论摘要
2. 联想词：各版本的高频联想及其褒贬，按分群
3. 好感变化：逐人配对的变化分布，按分群、按事前态度分层（原本喜欢的人和原本无感的人反应不同）
4. 可信、差异、契合三项评分
5. 危机回应专节：诚意、归责、行为；负面解读的主题
6. 传播专节（如有）：触达、再传播系数、说法变形链、听说者与亲见者的态度差
7. 稳定性、对照检验、不适用范围、模拟声明

## 5. 新增一个场景包要做什么

1. 在 `config/measures.yaml` 增加一节：量表项与行为选项（行为选项必须含 `none`）。
2. 在 `schemas/stimulus.schema.json` 与 `schemas/experiment.schema.json` 的 `pack` 枚举里加上新名字。
3. 写一份刺激物样例和一份实验样例，过校验脚本。
4. 写报告模板。
5. 用负对照和安慰剂跑一次冒烟实验，确认新量表分得出好坏。

人物库、引擎、分析底座不需要改。
