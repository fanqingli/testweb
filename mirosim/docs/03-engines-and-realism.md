# 03 推演引擎、拟真机制与可复现

## 1. 一次人物调用的完整过程

```text
输入：人物版本、世界快照、刺激物版本、重复编号、模型族
 1  曝光判定                     代码   §3
 2  记忆检索、既有态度            代码   docs/02 §5.4、§5.5
 3  行为参数                     代码   docs/02 §2.3
 4  渲染系统提示词与用户消息      代码   prompts/
 5  调用模型                     模型   经网关：先查录制，未命中才真调用
 6  录制原始输出                 代码   §7
 7  解析、校验                   代码   schema + 量表取值 + 字数
 8  不合格 → 带错误信息重试一次；仍不合格 → 记 valid=false
 9  写入反应表
```

第 5 步之外全是确定性的。这是可复现的基础：同样的输入加上同样的模型输出，后面每一步的结果都逐字节相同。

## 2. 确定性随机

系统里所有的「抽签」都用同一个函数（`tools/derive_behavior.py: u01`）：

```python
def u01(seed, *parts) -> float:          # 返回 [0, 1)
    key = "|".join([str(seed), *map(str, parts)]).encode()
    return int.from_bytes(hashlib.sha256(key).digest()[:8], "big") / 2**64
```

不使用全局随机数发生器。原因：并发执行时调用顺序不固定，顺序相关的随机数无法复现；而按键取值与顺序无关。

| 用途 | 键 | 说明 |
|---|---|---|
| 人群抽样 | `seed, "sample", segment_id, persona_id` | 分群内按该值排序取前 n 个 |
| 曝光 | `seed, "exposure", persona_id, replicate` | **不含版本号**，见下 |
| 曝光渠道 | `seed, "channel", persona_id, replicate` | |
| 谁发言 | `seed, "speak", persona_id, replicate, round` | 研讨模式 |
| 多数信号 | `seed, "majority", persona_id, replicate, round` | 研讨模式 |
| 转述是否发出 | `seed, "share", persona_id, replicate, step` | 传播模式 |
| 转述给谁 | `seed, "target", persona_id, replicate, step, k` | 传播模式 |
| 选项顺序 | `seed, "order", persona_id, measure_id` | 抵消位置偏好 |

**曝光的键不含版本号。** 同一个人物在同一次重复里，在所有版本下拿到的是同一个随机数，于是他要么在各版本下都看到了，要么都没看到。
版本之间的差别因此只来自内容，不混入「这次碰巧抽到了不同的人」。这是模拟实验里常用的公共随机数做法。

## 3. 曝光

| 设置 | 含义 | 用途 |
|---|---|---|
| `forced` | 每个人物都看到刺激物 | 测内容本身：条款好不好懂、文案有没有吸引力 |
| `natural` | 按渠道抽签决定看不看得到 | 测实际触达后的效果：没看到的人计入分母 |

自然曝光的算法：

```text
对人物 p、渠道计划 plan：
  p_seen = 1 − ∏_c (1 − reach_c × share_{p,c} × k)       c 遍历 plan 中的渠道
    reach_c    该渠道的投放触达率（刺激物配置）
    share_{p,c} 人物在该渠道上花的注意力占比（人物卡 media_diet，没有则为 0）
    k          归一化系数，缺省 2.0，使「主力渠道全量投放」时 p_seen 接近 1；写入清单
  exposed = u01(seed, "exposure", p, replicate) < p_seen
  若 exposed：按各渠道贡献的比例，用 u01(seed, "channel", ...) 抽一个作为看到它的渠道
```

没有被曝光的人物不调用模型，直接记一条 `exposed=false` 的反应。看到它的渠道会写进提示词（「你刷短视频时看到了这个」），因为同一句话在同行群里看到和在官方通知里看到，分量不同。

曝光之后还有第二道关：人物自己答的 `noticed`。看到了但没在意，是真实的常态，照实计入。

## 4. 传播

每一步，对上一步回答 `would_share = true` 的人物：

```text
1  过转述抽签：u01(seed, "share", p, replicate, step) < share_propensity(p)
     —— 说愿意转的人里只有一部分真的转了。压的是「人人转发」这一失真
2  确定接收者，最多 fanout 个（缺省 3）：
     候选 = 与 p 有关系的库内人物 ∪ 与 p 同分群且共用某个社交类渠道的人物
     权重 = 关系强度（无关系的同渠道人物取 0.1）
     人物自己说的 to_whom 用来筛候选类别（同行、家人、朋友）
     按权重用 u01(seed, "target", ...) 无放回抽取
3  接收者下一步收到的是 p 的 share.what 原话，不是刺激物原文
     同一步内收到多条转述的，全部给出，最多 3 条，按关系强度取
4  已经看过原文的接收者：提示词里注明「这事你之前自己看到过」
```

度量：

| 指标 | 算法 |
|---|---|
| 每步触达 | 累计被曝光人数 / 总人数 |
| 再传播系数 | 每步新增被曝光人数 / 上一步实际转述人数；持续小于 1 说明传不开 |
| 说法变形 | 对每步的转述原话做主题编码，统计与原文要点不符的比例及主要变形方向 |
| 态度走向 | 每步的态度均值与分布，按「直接看到原文」和「听别人说的」分开 |

传播模式的结果对关系图的密度非常敏感。库内关系稀疏时，系统会在报告里注明「候选主要来自同渠道推定，而非人物间的既有关系」。

## 5. 十二种已知失真与对策

每一条都有压它的机制和量它的指标。指标在每次实验的质检步骤里计算；标「闸门」的不达标时不出结论报告。

| # | 失真 | 表现 | 机制 | 指标与门槛 |
|---|---|---|---|---|
| 1 | 讨好 | 对什么方案都说好 | 系统提示词规矩 1、3；负对照版本 | 负对照的吸引力或支持度须明显低于所有候选（**闸门**，§6） |
| 2 | 参与度虚高 | 人人认真读完、人人有看法 | `noticed` 字段；允许 `dk`；行为选项必含「什么都不做」；自然曝光 | 强制曝光下 `noticed=false` 与 `none` 行为的合计占比 < 5% 时告警 |
| 3 | 趋中与方差压缩 | 回答挤在中间档 | 人物连续分值；较高的采样温度；骨架由代码抽样 | 各量表题的标准差；与安慰剂之间的差相比，人物之间的差应大一个量级以上 |
| 4 | 脸谱化 | 同一类人说同样的话 | 分群内倾向至少覆盖两档；人物有一处与身份不相称；同组合人数上限 | 分群内立场的熵；同分群原话两两相似度的 90 分位 < 0.80 |
| 5 | 过度理性 | 人人条分缕析、权衡利弊 | 先写第一反应再打分；字数上限；知识边界；软渲染中的直觉型描述 | 原话中出现「首先/其次/综上」等结构词的比例 < 5% |
| 6 | 全知 | 普通人懂法条、懂成本结构 | 知识边界；只给人物其渠道上看得到的内容 | `takeaway` 抽样人工核对：是否出现人物不应知道的信息 |
| 7 | 人人转发 | 说会转的比例远高于常理 | 转述抽签 | 实际转述率；再传播系数 |
| 8 | 立场摇摆 | 被一句话说服，或重复之间立场乱跳 | 立场变动上限；私下立场与公开立场分开 | `suspicious_shift` 比例；重复间同一人物立场一致率（§7.3） |
| 9 | 快速共识 | 两轮之后全场一致 | 多数信号按人抽签给出；发言权按倾向分配；利益约束常驻提示词 | 末轮私下立场的分歧度不应低于首轮的一半，除非方案本身有实质让步 |
| 10 | 模型口吻 | 「作为一名……」「这是一个复杂的问题」 | 系统提示词规矩 5；说话方式字段 | 黑名单短语命中率 < 2% |
| 11 | 顺序与位置偏好 | 偏选第一个选项 | 选项顺序按人物随机 | 各选项被选比例与其出现位置的相关 |
| 12 | 模型自身的倾向 | 某个模型整体偏乐观或偏谨慎 | 多模型族对照；分析模型与人物模型不同族 | 模型族之间版本排序的一致性（§7.3） |

对第 3、5 两条要有清醒的预期：`docs/00` §5 所引的研究表明，更丰富的人物档案能减轻方差压缩，但过度理性在经济选择上没有改善。本设计的机制能压低表面症状，不能保证根除，所以才需要 §6 的对照和 `docs/05` 的校准。

## 6. 三种对照

| 对照 | 是什么 | 用来回答 | 判定 |
|---|---|---|---|
| 现状 `status_quo` | 「什么都不变」的版本 | 候选方案比不动更好还是更差 | 作为所有比较的基准。政策包必备 |
| 安慰剂 `placebo` | 内容与某个候选逐字相同，换个编号再跑一遍 | 两个完全相同的东西，系统会测出多大的「差别」 | 它与原版本之间的差，就是本次实验的噪声底。候选之间的差不超过噪声底的，一律报告为「无法区分」 |
| 负对照 `negative_control` | 一个明显差的版本（空话连篇、价格离谱、条款明显不公） | 系统分不分得出好坏 | 它的得分若不明显低于候选，判定存在讨好偏差，本次实验结论作废 |

「明显低于」的操作定义：主要指标上，负对照与每个候选的配对差的 95% 区间不含零，且方向为负对照更差（算法见 `docs/05` §2）。

每个正式实验至少包含安慰剂；营销包与品牌包另加负对照；政策包另加现状。校验脚本会检查安慰剂的内容是否与其对应版本逐字相同。

## 7. 可复现：分成两件事

### 7.1 回放

每一次模型调用，按下面的键把完整的请求和原始响应存下来：

```text
call_key = sha256(run_id + 用途 + 模型 id + 全部采样参数 + 系统提示词 + 用户消息 + 调用序号)
```

`run_id` 必须在键里：安慰剂与其对应版本、同一版本的各次重复，提示词逐字相同，但要各自独立调用；键里没有它，这些调用会合并成一条录制，噪声底恒为零。调用序号用于区分同一次运行内「同样的输入、有意重复调用」的情形（例如重试）。回放时网关只查录制、不发请求。

**要求：任何一次实验，用其清单和录制回放，得到的反应表、分析结果、报告，与原来逐字节一致。** 这是 100% 的要求，没有阈值。达不到就是代码里有不确定性（未排序的集合、时间戳、未固定的浮点运算顺序），要当缺陷修。

回放解决的是：三个月后有人质疑结论，可以原样重算；分析方法改进后，可以在旧数据上重新分析而不必重新花钱调用。

### 7.2 重跑稳定性

重新调用模型，输出一定会变。这不是缺陷，要量的是：结论变不变。

每个实验的 `replicates`（缺省 3）就是内置的重跑。稳定性指标：

| 层级 | 指标 | 算法 |
|---|---|---|
| 人物 | 立场一致率 | 同一人物、同一版本，在各次重复里立场相同的比例 |
| 分群 | 分布差异 | 各次重复之间，分群立场分布的总变差距离 |
| 结论 | 排序一致 | 各次重复各自得出的版本排序，两两之间的 Kendall τ |
| 结论 | 主题重合 | 各次重复各自的前五位反对理由，两两之间的 Jaccard |

研讨模式沿用 v3.0 §11.3 的公式（0.4 × 命题 Jaccard + 0.4 × 立场一致率 + 0.2 × 结论 Jaccard）。

### 7.3 报告里怎么写

- 人物层面的立场一致率照实报告，不设及格线。真人隔两周重答也只有八成左右一致；这个数接近 1 反而说明人物被写死了。
- 结论层面设闸门：各次重复的版本排序里，第一名不一致的，报告写「领先者不稳定」，不给排序结论。
- 换模型族之后排序改变的，两个排序并列给出，标注「结论依赖于模型」。
- 清单里的 `randomness.rerun_stability` 记录上述数值；`replayable` 记录回放校验是否通过。

模型换代时（v3.0 §9.7），用新模型对最近若干个已归档实验做一次重跑，稳定性指标写入模型更换记录，作为「历史结论还能不能和新结论放在一起比」的依据。
