# 07 实施计划

## 1. 分期

每一期都以「能跑出一样可检验的东西」为结束标志。工期按一名熟悉 Python 的工程师全职投入估计，是相对量，不是承诺。

### 第 0 期：打底与验证假设（约 1 周）

| 任务 | 产出 | 验收 |
|---|---|---|
| 盘点 v2.6 现有代码 | 一份清单：哪些模块可直接用、哪些要改、哪些弃用 | 对 v3.0 所列模块逐一给出结论 |
| 工程骨架 | `pyproject.toml`、`src/mirosim/core/`、数据库建表、CI | `tools/validate_examples.py` 接入 CI 并通过 |
| 模型网关 | 录制、回放、重试、档位 | 同一请求第二次调用不发出网络请求；回放模式下断网可运行 |
| 选定模型 | 每个档位的主、备模型；实测单价 | `config/model_tiers.yaml` 填实；各候选模型的探针结果对比表 |
| 手写 20 张人物卡 | 覆盖 16 种类型，含 4 个边界型 | 通过 schema 校验 |
| 编写探针题库 | 54 道情境迫选题 | 人工审定；20 张卡的 `trait_recovery` 中位数 ≥ 0.70 |
| **检验映射表** | 每条轴的卡上分值与探针得分的相关 | 每条轴 ≥ 0.40；不达标的改写软渲染文字后重测 |

第 0 期是一个真正的检查点。如果反复改写后，某条轴始终无法让模型表现出可测的行为差别，就如实记录，并把那条轴降级为「仅作标签，不参与行为」。继续往下做的前提是至少 E/I 和另外两条轴可用。

关于 v2.6 代码：本设计撰写时只看到 v3.0 文档，未见代码。建议的缺省方案是新写内核（存储、网关、人物、群体反应引擎），到第 3 期再把 v2.6 的研讨与分析模块按 v3.0 的修订接进来。盘点后若发现 v2.6 的调度与存储质量足够，可以调整。

### 第 1 期：群体反应模式跑通（约 2–3 周）

| 任务 | 产出 |
|---|---|
| 人物工厂 | 骨架抽样、模型写人、质检入库 |
| 人群抽样与权重 | 按人群框架抽样；复用优先 |
| 群体反应引擎 | 强制曝光与自然曝光；并发执行；断点续跑 |
| 基础分析 | 汇总、配对差、噪声底 |
| 质检 | 十二项指标中适用于群体反应的九项；安慰剂与负对照闸门 |
| 报告 | 营销包与政策包的 Markdown 报告 |
| 清单与回放 | 完整清单；`replay --verify` |

**验收：**

1. 用 `examples/experiment.marketing.yaml`（300 人、4 个版本、3 次重复）完整跑通，从配置到报告无人工干预。
2. `replay --verify` 通过：回放结果与原结果逐字节一致。
3. 负对照版本的吸引力得分明显低于三个候选（`docs/03` §6 的判定）。
4. 在同一实验中加入版本 A 的安慰剂，其与 A 的差落在预期的噪声范围内，且小于候选之间最大的差。
5. 请三位不了解系统的人各读 30 条随机抽取的原话，判断「像不像这样一个人会说的话」，认可率 ≥ 70%。

到这里，系统处于 L0，可以开始用于内部的定性探索。

### 第 2 期：长期档案与稳定性（约 2 周）

| 任务 | 产出 |
|---|---|
| 记忆与世界 | 检索、分支、封存、提交、反思 |
| 态度 | 态度表、事前事后配对 |
| 世界事件 | 批量写入 |
| 主题编码 | 两遍编码、证据回查、一致性检验 |
| 稳定性 | 重复间指标；多模型族对照 |
| 品牌包 | 量表、基线调用、报告 |
| 漂移检查 | 三项检查 |

**验收：**

1. 隔离性测试：同一人物在版本 A 的分支里写入记忆后，在版本 B 的分支和基准世界中均检索不到。
2. 连续性测试：把一个实验的版本 B 提交进基准世界，再跑一个涉及同一对象的新实验；人物的反应中提及此前经历的比例显著高于未提交的对照组，且提及内容与提交的记忆相符。
3. 回测隔离：把 `as_of_date` 设在某条记忆之前，该记忆不被检索到。
4. 两个模型族在营销样例上给出相同的版本排序；若不同，报告正确地标出「结论依赖于模型」。
5. 主题编码的证据回查通过率 100%；抽检准确率 ≥ 85%。

达到这些，系统在已测的场景包与人群上认定为 L1。

### 第 3 期：研讨模式（约 3 周）

| 任务 | 产出 |
|---|---|
| 接入 v3.0 的研讨设计 | 五轮结构、剧本、主持人；按第 0 期的盘点结论移植或重写 |
| 发言控制 | 发言抽签、字数上限、多数信号、私下立场 |
| v3.0 分析模块 | 命题级共识、权重投票、人物画像（入度与采纳度）、关系图 |
| 漏斗 | 从群体反应结果中按规则挑人 |
| 政策包完整报告 | 含研讨结果一节 |

**验收：** 沿用 v3.0 第 11 章的模块级门槛，另加三条：

1. 发言量分布：高发言倾向的人物的实际发言次数，显著多于低发言倾向的人物。
2. 表面服从可测：在有权力差距的场次里，私下立场与公开立场不一致的比例高于没有权力差距的对照场次。
3. 同一批人物、两个版本各开一场，共识模块给出的结论不同之处，能对应到版本内容的差别。

### 第 4 期：传播模式、接口与校准（约 3–4 周，可拆开）

| 任务 | 产出 |
|---|---|
| 传播引擎 | 转述抽签、接收者选择、分步执行、变形分析 |
| 接口服务 | `docs/06` §5 |
| 回测 | 至少 5 个历史案例的预登记与对照 |
| 真实问卷对照 | 对照工具与修正表 |
| 运维 | 备份、监控、密钥管理（沿用 v3.0 第 13 章） |

**验收：** 传播样例跑通，再传播系数与说法变形链可在报告中查看；回测流程走通至少一个案例。L2、L3 的认定取决于数据，不作为本期的验收条件。

## 2. 依赖关系

```text
第 0 期 ──▶ 第 1 期 ──▶ 第 2 期 ──┬──▶ 第 3 期
                                  └──▶ 第 4 期（传播依赖记忆分支；接口与校准可随时开始）
```

政策评估若急用，可在第 1 期后先用群体反应模式做条款措辞的比较，研讨部分暂时沿用 v2.6 的现有能力。

## 3. 第一个实验怎么选

建议从营销包的文案比较开始，而不是政策：

- 刺激物短、版本差别清楚，容易判断系统有没有分辨力；
- 容易拿到现实对照——同一品牌过去投放过的两版文案及其实际表现，或一次几十人的小问卷；
- 出错的代价低。

政策场景利益结构复杂、现实结果滞后且难以归因，适合在系统通过了营销场景的检验之后再上。

## 4. 人员与分工

| 角色 | 职责 | 投入 |
|---|---|---|
| 工程 | 内核、引擎、分析、报告 | 全程 |
| 研究设计 | 量表、探针题库、人群框架、对照设计、结果解读 | 第 0–2 期重点投入，之后每个实验参与 |
| 领域顾问 | 审人物卡是否合乎该行业的实际；审刺激物是否写得像真的 | 每批人物、每个实验各一次 |
| 实验负责人 | 立项、确认预算、签发报告、决定提交 | 每个实验 |

研究设计这个角色不能省。系统能不能给出可信的结论，一半取决于问题问得对不对、对照设得对不对，这不是工程问题。

## 5. 主要风险

| 风险 | 可能的后果 | 应对 |
|---|---|---|
| 映射表不起作用：性格写进提示词后，行为差别测不出来 | 「不同 MBTI 的人物」名不副实 | 第 0 期先验证；硬控制参数不依赖模型，始终有效；不起作用的轴降级为标签 |
| 结论随模型而变 | 换一个模型，排序就反过来 | 正式结论须两个模型族一致；不一致时并列报告 |
| 中文语境下的效度未知 | 现有研究多基于美国受试者，不能直接搬用 | 尽早做一次小规模真实问卷对照；在此之前只下 L1 的结论 |
| 被当成真实民意引用 | 合规与声誉风险 | 报告生成器按效度等级裁剪；所有导出物带声明与水印；`forbidden_claims` 写进实验配置 |
| 人物库同质化 | 结论反映的是模型的平均看法 | 骨架由代码抽样；区分度指标；访谈派生的人物逐步加入 |
| 成本超预期 | 实验做不起，只好减人数减重复 | 启动前估算并设上限；先小规模探索；前缀缓存 |
| 模型换代 | 历史结论与新结论不可比 | 录制保证旧实验可回放；换代时重跑归档实验并记录差异（`docs/03` §7.3） |
| 人物被实验塑造 | 复用越多越失真 | 默认不写记忆；只提交现实；漂移检查 |

## 6. 合规与边界

沿用 v3.0 第 12 章的全部要求。本设计把其中几条写进了数据契约和程序，使其不依赖使用者自觉：

| 要求 | 落实方式 |
|---|---|
| 人物是合成的 | `persona.schema.json` 中 `synthetic` 只能为 `true`；每张卡带声明 |
| 不得使用真实姓名、真实机构 | 人物工厂的提示词约束 + 入库前的实名筛查 |
| 所有产出带模拟声明 | 实验配置与清单中 `notice` 必须为 `SIMULATION_NOTICE_v1`；报告模板首尾固定包含 |
| 不得冒充真实调查 | 报告生成器按效度等级裁剪；`forbidden_claims` 由立项人逐条填写并印在报告首页 |
| 引用原话须可辨识为模拟 | 每条引语带人物编号与「模拟人物」标记 |
| 访谈派生人物 | 须有受访者同意；去标识；一个人物不得只对应一位受访者 |
| 真实品牌与真实机构作为刺激物 | 允许出现在刺激物里（否则无法评估真实方案），但报告须注明模型对其自带印象不可控；不得生成以真实个人为对象的评价 |
| 数据留存 | 录制与反应长期保留以供回放；含真实访谈材料的原始数据按 v3.0 §12.4 处理 |

**不应使用本系统的场合：** 替代法定的征求意见或听证程序；对具体个人的行为或态度作判断；生成用于公开传播的「民意」内容；任何把模拟结果呈现为真实人群意见的用途。

## 7. 现在可以做的第一步

```bash
cd mirosim
python -m venv .venv && . .venv/bin/activate
pip install jsonschema pyyaml
python tools/validate_examples.py                           # 校验全部样例
python tools/derive_behavior.py examples/personas/p_0a31f7.json --power-gap 0.8
```

然后按第 0 期的任务表开始：先定模型、写探针题库、手写 20 张人物卡，把映射表验证一遍。
